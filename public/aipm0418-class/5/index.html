開場故事：女兒的 Canva 牛奶簡報

📖 STORY TIME

女兒回家說學校要做推廣牛奶的 Canva 簡報 — 主題：全脂牛奶健康、低脂牛奶容易長痘痘。

講者用 AI 幫女兒做了一個「牛奶挑戰小遊戲」：喝低脂 → 長一顆痘痘；喝全脂 → 消一顆痘痘。

重點不是做了什麼，而是「用女兒懂的語言去教她數學」— AI 可以把抽象概念變成她的語言。

「AI 是全世界最聰明的一種生物。我每次都請 AI 用我們自己的語言來教我 — 這就是 AI 最大的學習加速器。」

公司案例：內部 AI agent「點點學姐」（豆乳）

  • 公司內部的 AI agent，名字叫「點點」，英文叫「豆乳 / Dot Dot」
  • 有自己的 IG、有自己的個性，是內部「數位元老」
  • 每次發文風格、穿著、配件要一致 — 這才是生成圖像最難的地方
  • IG 內容範例：三星智慧電視 ACR 偷偷截圖的隱私問題 → 畫面是「點點看電視 / 電視看點點」雙視角
  • 點點會回 IG 留言、處理 follow-up — 像真的同事

產品 PM vs 專案 PM

角色問的問題關注核心價值交付
產品 PM要做什麼？為誰做？有人要嗎？市場與用戶價值Build the right thing（做對的事）
專案 PM怎麼做？能做完嗎？如期嗎？資源與交付效率Do things right（把事做對）
「產品重點要偏右腦 — 感性、想像力；專案重點偏左腦 — 邏輯、優先順序。兩者缺一不可。」

即使是公司內部產品，也要做目標客群分析 — 不然同事不用，白做。

Notion 是什麼

整合筆記、文件、資料庫、協作的 All-in-one 生產力工具。練習：登入 → Private 旁「+」→ 建第一頁 → 試試 /h1, /h2, /code 等 block。

Notion 的核心概念：不是 Word 每行決定字大小，而是「每個東西都是一個 block（區塊）」。

四種關鍵文件格式

格式特性用在哪
Markdown人讀 AI 讀都清楚PRD、筆記、核心流程
JSONKey-Value 結構，機器最好處理API 傳遞、Function Calling
HTML/CSS/JS終端使用者介面網頁、應用
Mermaid以文字描述的流程圖與架構圖流程分析、PRD 前先畫

Markdown 速記

  • #（井號 / 景號）+ 空格 = 標題（# 最大、## 次大、### 再次）
  • **粗體** — 前後各兩個 star
  • --- — 三個 dash = 橫線分隔
  • - 項目 — 清單

JSON 五大符號

  • { } 大括號 — 一個完整的物件
  • [ ] 中括號 — 一份陣列（清單）
  • "..." 雙引號 — 包住文字與標籤
  • : 冒號 — 分隔標籤與資料
  • , 逗號 — 分隔下一筆

HTML / CSS / JS 大樓比喻

  • HTML = 建築物的鋼筋與牆面（結構）
  • CSS = 幫建築物上色、裝潢、擺傢俱（樣式）
  • JavaScript = 電梯、開關、感應系統（互動與邏輯）

練習：LINE 請假小幫手（aipm048 原型）

實作流程：

  1. 用 Gemini 生成 JSON product description（Product_name、Core_features、user_flow、input、output）
  2. 用 Gemini Canvas 從 JSON 生成對應畫面（Canvas 的背後就是 HTML）
  3. 用 Mermaid 畫 Flowchart + Sequence Diagram
  4. 產生 PRD（Markdown 格式）

💡 aipm048 專案中的 Line 請假小幫手 MCP 架構圖，正是這個練習的延伸版本。

Mermaid：用文字畫圖

Flowchart（流程圖）5 大用途

  1. 描述整體業務流程（訂單、請假等）
  2. 規劃系統邏輯（if / else decision flow）
  3. 與 Stakeholder 溝通需求（寫 PRD 前先畫流程）
  4. 作為開發前的設計草稿
  5. Debug 與問題排查（找 bottleneck）

Sequence Diagram（序列圖）5 大用途

  1. 描述系統之間的互動（Frontend → Backend → DB）
  2. 設計 API 呼叫流程（request / response 順序）
  3. 描述非同步 / 即時系統（WebSocket、pub-sub）
  4. 分析系統責任分工
  5. Debug 跨服務複雜問題（支付失敗 → payment API 還是 DB？）

SEO 的終結：GEO 時代來了

SEO（Search Engine Optimization）過去 20 年的顯學 — 讓 Google 好爬、好索引、排名高。

GEO（Generative Engine Optimization）是 AI 時代的新顯學 — 讓 AI 引擎看得懂你的網站、並在產生答案時引用你。

Zero Click Search 現象

  • 過去：Google 搜尋 → 點開第 1 頁、第 2 頁、比較、找答案
  • 現在：AI 直接給答案 → 使用者連點都沒點
  • 結果：傳統 HTML 對 AI 不太友善 — 要加 Markdown 版本的介紹（針對每個頁面寫給 AI 看的描述）

AI Friendly 設計

  • 同樣的網站架構下，為每個頁面寫一份 Markdown 介紹讓 AI 能讀
  • 使用 MCP 接口，讓 AI 能安全地存取資料
  • 考慮「內容能被 AI 引用」而非只是「被點進來看」

Prompt 三段式：System / User / (Context)

API 呼叫 LLM 時，通常分兩段：

  • System Prompt：設定 AI 的 Persona（角色人格）
  • User Prompt：使用者的當下問題

用網頁 / App（如 Gemini）時兩者合在一起 — 但知道它們可以分開很重要，因為這正是系統化導入的關鍵。

AI 產出的過濾：AI 給你 60 分，你要補到 90

「AI 寫出的東西可能是 60 分，勉強完整。人還是要修改、消化、判斷 — 等到人沒有角色的時候，你就要開始擔心自己的位置了。」
  • AI 產出一定要過濾 — 別交給別人一份自己沒看過的 AI 報告
  • 優化一份寫好的產品分析 — 比從零生成更簡單
  • PM 要做的是：掌握每個輸入與輸出，才能把節點串聯起來
  • 一個小地方掌握不好 → 串聯後更亂

本課重點

  • 1. AI 四階段：選模型 → Prompt → RAG → RPA/Vibe Coding，每週推進一階。
  • 2. 產品 PM vs 專案 PM：前者問「做什麼」偏右腦，後者問「怎麼做」偏左腦。
  • 3. 四種格式：Markdown（人+AI）、JSON（API）、HTML（UI）、Mermaid（圖）。
  • 4. Notion：block-based，/h1 /code 是基礎招式。
  • 5. LINE 請假小幫手練習：JSON → Gemini Canvas 產畫面 → Mermaid 畫流程。
  • 6. GEO 時代：SEO 是過去 20 年，GEO 是未來 — 要為 AI 寫 Markdown 介紹、裝 MCP。
  • 7. 用女兒的語言：用 AI 學東西，請它「用我懂的語言教我」。
  • 8. AI 給 60 分：人要補到 90 — 掌握每個節點的輸入輸出，不做「AI 代筆的轉包商」。
