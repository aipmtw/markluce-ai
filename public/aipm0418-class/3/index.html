提升 LLM 能力的 3 種方法

方法是否訓練用途
Prompt Engineering❌ 不訓練用指令 + 範例調教預訓練 LLM；最快，但受限於模型內建知識
RAG（檢索增強）❌ 不訓練Prompt 前先從外部資料庫撈「剛剛好的資料」→ 補進 Prompt；解決幻覺與知識靜態
Fine-tuning✅ 要訓練用特定領域資料集微調模型；最昂貴但最客製化

階段人類角色實例

AI Agent 的本質：自動駕駛飛機

最好的類比：現代飛機的自動駕駛。起飛降落需要人，巡航階段交給自動駕駛，飛行員負責「看著它」。

  • 機長 + 副機長 = PM + 工程師（監督者）
  • 飛行計畫 = Prompt / 任務規劃（起飛點、目的地、備案備降機場）
  • 自動駕駛系統 = AI Agent（執行者）
  • 機艙模擬機 = Sandbox / 沙箱訓練環境

起點參考：Office 早期的 Clippy 小幫手 — 那就是最早的 AI assistant 雛型。

AI Agent 架構組成（Lil'Log 框架）

標準 Agent 四件套：

  • Planner（規劃者）：任務拆解、制定步驟
  • Tool Use（工具呼叫）：呼叫 API、資料庫、外部服務
  • Memory（記憶）：短期 + 長期記憶管理
  • Executor（執行者）：實際跑任務

MCP：讓 AI 看得懂網站的「第二個介面」

2026 年各家軟體開始提供 MCP (Model Context Protocol) 接口 — Anthropic 提出的開放標準，讓語言模型能安全存取資料與工具。

「以後的網頁可能有兩個版本 — 一個給人看，一個給 AI 看。AI 能看懂的網站會越來越多。」

電通 UI/UX 團隊實測

  • 2 月初推出時用，細節處理還不夠好 → 還是要人工介入
  • 上個月持續實驗 → 流程漸漸順暢
  • 結論：MCP 能處理大部分，「細節」仍是人的戰場

Google A2A：Agent 跟 Agent 對話的協定

A2A（Agent2Agent Protocol）是 Google 推的開放標準，解決「多個 agent 怎麼互相協作」：

  • 不同代理間 不需共享記憶體、資源、工具即可動態、多模式通訊
  • MCP 負責 Agent ↔ Tool；A2A 負責 Agent ↔ Agent
  • 支援 Google ADK、LangGraph、Crew.AI
  • 社區推動的開放標準

生活場景示例

冰箱 agent 看到青菜快用完 → 主動呼叫家樂福 agent 和全聯 agent 比價 → 下單 → 送到家。

寫三明治實驗：為什麼 Prompt 要精確

經典梗：爸爸要孩子教他「怎麼做三明治」，孩子說「把麵包拿出來」→ 爸爸直接把整包麵包丟到桌上。

「每一步都要講清楚 — 這就是為什麼產品規格要寫得那麼詳細。不講清楚，AI 就會照你模糊的描述邊界，產出你根本不要的東西。」

Gemini Prompt Framework：四個要素

🎯 Gemini 官方推薦的 Prompt 結構
  1. 角色（Role）：你是一個誰？例：「你是資深 AI Product Manager」
  2. 任務（Task）：你要做什麼？例：「撰寫 PRD / 產出 User Stories」
  3. 背景資訊（Context）：產品名、目標用戶、痛點、技術限制 — 像韓劇每集開頭「上集回顧」
  4. 格式（Format）：輸出成什麼？條列、表格、Markdown、HTML、Mermaid...

HTML 格式是講者內部最愛的輸出 — 快速預覽、不懂程式的人也能改。

CRISPE Framework（另一種結構）

  • Capacity and Role — 能力與角色
  • Insight — 洞察力（背景資訊、上下文）
  • Statement — 指令（希望 AI 做什麼）
  • Personality — 個性（回應風格）
  • Experiment — 嘗試（要求多個答案）

口訣：定角色、敘背景、提要求、定風格

Prompt Engineering 的極限 → Context Engineering

光寫 Prompt 的三大缺點：

  • 窗口有限 / 過載：全塞入會造成「雜訊爆炸」→ 準確率下降約 24.2%。解法：RAG 動態檢索。
  • 幻覺無法根治：只靠內建知識 → 過時或虛構內容。解法：外部知識庫當 Grounding 來源。
  • 知識靜態：Prompt 固定 → 無法反映市場變化。解法：長期記憶 + 即時檢索。

參數調校：Temperature / Top-p / Top-k

參數範圍說明
Temperature0 – 2（預設 1）低溫 = 保守、故事平淡；高溫 = 創意、故事有趣但可能奇怪
Top-p0 – 1選「機率加起來達到一定值」的詞彙
Top-k整數從「機率最高的前 k 個詞」中選

🐎 Harness Engineer：馬具工程 / 韁索工程

Agent = Model + Harness

  • Model = LLM（Claude、Grok、GPT）負責思考與生成
  • Harness = 圍繞 Model 的基礎設施（非 Prompt / Context）負責長期自主運行、可信賴、可監控、可恢復

「Harness 就像給一匹野馬套上馬鞍、韁繩、導航系統與安全機制 — 讓它能安全地跑完長途賽事，而不是只會在原地亂跑。」

PM 如何參與 Harness 設計（不需要寫 Code）

  • 定義 Agent 的 Success Criteria 與 Failure Recovery
  • 設計「外層 Harness」讓工程團隊快速落地
  • 參考案例：OpenAI Codex、Anthropic Long-Running Agent
  • 風險管理與合規：幻覺控制、漂移監控、成本控制、法律合規

4 種 Engineer 的演進路線

Prompt Engineer → Context Engineer → Agentic Engineer → Harness Engineer
  • Prompt Engineer：寫好指令
  • Context Engineer：用 RAG 補充外部知識，解決幻覺
  • Agentic Engineer：設計 Agent（Planner/Tool Use/Memory/Executor）
  • Harness Engineer：設計讓 Agent 長期運行的環境

Canva ByCoding 實作 Demo

  • 從 1-2 句話 → 讓 AI 自己產出完整 Prompt → 讓 AI 自己審查自己的 Prompt
  • 就像工程師寫程式：先做一個會動的雛型（大方向）→ 再新增細節小功能
  • Mermaid 語法輸出：讓 AI 自己畫流程圖 / 使用者情境圖
  • Thinking 模式：講者認為效果比較好（體感層面）

本課重點

  • 1. LLM 能力提升 3 法：Prompt / RAG / Fine-tuning，依需求選擇。
  • 2. AI 未來 4 階段：Embedded → Copilot → Agent → Society。
  • 3. Agent 四件套：Planner + Tool Use + Memory + Executor。
  • 4. MCP vs A2A：MCP 是 Agent↔Tool；A2A 是 Agent↔Agent。
  • 5. Prompt 兩大框架：Gemini（角色/任務/背景/格式）、CRISPE（能力/洞察/指令/個性/嘗試）。
  • 6. 三明治法則：規格寫不細，AI 就亂做。
  • 7. Engineer 演進：Prompt → Context → Agentic → Harness。
  • 8. Harness Engineer：給 Agent 套上馬鞍 — 是 PM 最有機會貢獻的新角色。
